# Type Casting in JavaScript

**Type casting** (also called **type conversion**) is the process of converting a value from one data type to another.

---

## 🎯 Type Conversion vs Type Coercion

### Definitions

| Term                | Meaning                                      | Who Controls It?                    |
| ------------------- | -------------------------------------------- | ----------------------------------- |
| **Type Conversion** | Converting a value from one type to another  | General term (implicit or explicit) |
| **Type Coercion**   | **Automatic** type conversion by JavaScript  | JavaScript engine (implicit)        |
| **Type Casting**    | **Manual** type conversion by the programmer | Developer (explicit)                |

> [!NOTE] > **The Relationship**
> Type coercion is a **subset** of type conversion. All coercion is conversion, but not all conversion is coercion!

```
Type Conversion = Implicit (Coercion) + Explicit (Casting)
```

---

## ⚡ Implicit Type Casting (Type Coercion)

JavaScript automatically converts types to make operations work. This can be helpful but also cause bugs!

### 1️⃣ Arithmetic Operators (Auto-convert to Number)

Operations like `-`, `*`, `/`, `%` convert strings to numbers.

```js
"5" * 2; // 10   → "5" converted to 5
"10" - 1; // 9    → "10" converted to 10
"6" / "3"; // 2    → both converted to numbers
"15" % 4; // 3    → "15" converted to 15
```

> [!TIP] > **Quick Number Conversion Trick**
> Multiply by 1 or subtract 0 to convert strings to numbers quickly:

```js
"42" * 1; // 42
"42" - 0; // 42
```

---

### 2️⃣ The `+` Operator (Special Case!)

The `+` operator behaves differently: **if any operand is a string, it concatenates**!

```js
// String concatenation
1 + "2"; // "12"  → number 1 becomes string "1"
"2" + 1; // "21"  → number 1 becomes string "1"
"Hello" + 5; // "Hello5"

// Numeric addition
1 + 2; // 3
```

> [!WARNING] > **Common Gotcha**
> This can lead to unexpected results:

```js
let result = "5" + 3 - 2;
console.log(result); // "53" - 2 = 51 (not 6!)

// Breakdown:
// "5" + 3    →  "53" (string concatenation)
// "53" - 2   →  51   (string to number conversion)
```

---

### 3️⃣ Loose Equality `==` (Auto Type Conversion)

The `==` operator performs type coercion before comparison.

```js
0 == false; // true  (0 and false both become falsy)
"" == 0; // true  (both become 0)
null == undefined; // true  (special rule)
"5" == 5; // true  ("5" converted to 5)
```

> [!CAUTION] > **Use Strict Equality!**
> The `==` operator can cause subtle bugs. **Always use `===`** (strict equality) to avoid type coercion.

```js
// BAD
if (value == 0) {
}

// GOOD
if (value === 0) {
}
```

**Comparison:**

| Operator | Type Conversion | Recommended |
| -------- | --------------- | ----------- |
| `==`     | ✅ Yes          | ❌ Avoid    |
| `===`    | ❌ No           | ✅ Use this |

---

### 4️⃣ Boolean Context (Truthy/Falsy)

In conditions, JavaScript converts values to boolean.

```js
if ("hello") {
	// truthy
	console.log("Runs!");
}

if (0) {
	// falsy
	console.log("Doesn't run");
}

// Double NOT (!!) converts to boolean explicitly
!!"hello"; // true
!!0; // false
!![]; // true (empty array is truthy!)
!!{}; // true (empty object is truthy!)
```

> [!IMPORTANT] > **The 7 Falsy Values**
> Only these values are falsy in JavaScript. Everything else is truthy!

```js
Boolean(false); // false
Boolean(0); // false
Boolean(-0); // false
Boolean(""); // false (empty string)
Boolean(null); // false
Boolean(undefined); // false
Boolean(NaN); // false
```

---

### 5️⃣ Other Coercion Examples

#### Unary Plus `+`

```js
+"42" + // 42
	"3.14" + // 3.14
	true + // 1
	false + // 0
	null + // 0
	undefined; // NaN
```

#### Bitwise Operators

```js
3.9 | 0; // 3 (converts to 32-bit integer)
5.7 >> 0; // 5
~~4.8; // 4 (double bitwise NOT)
```

#### Comparison Operators `<`, `>`

```js
// Both strings → lexicographic comparison
"2" > "12"; // true ("2" comes after "12" alphabetically)

// Mixed types → convert to numbers
"2" > 12; // false (2 > 12)
10 > "5"; // true (10 > 5)
```

## 🎨 Explicit Type Casting

You **manually specify** the target type. This is clearer and safer!

### 1️⃣ String → Number

#### Using `Number()`

```js
Number("3.14"); // 3.14
Number("42"); // 42
Number("42px"); // NaN (fails gracefully)
Number(""); // 0
Number(" "); // 0
```

> [!TIP] > **Recommended Method** > `Number()` is the most explicit and clear way to convert strings to numbers.

#### Using `parseInt()` (For Integers)

```js
parseInt("08", 10); // 8
parseInt("42px", 10); // 42 (stops at first non-digit)
parseInt("3.14", 10); // 3 (discards decimals)
parseInt("abc", 10); // NaN
```

> [!WARNING] > **Always Specify Radix (Base)**
> Always provide the second parameter (radix) to avoid unexpected results:

```js
parseInt("08"); // 8 (modern browsers)
parseInt("08", 10); // 8 (explicit, safer)
parseInt("08", 8); // 0 (octal interpretation)
```

#### Using `parseFloat()` (For Decimals)

```js
parseFloat("2.5px"); // 2.5
parseFloat("3.14"); // 3.14
parseFloat("abc"); // NaN
```

#### Using Unary Plus `+` (Quick but Less Clear)

```js
+"42" + // 42
	"3.14"; // 3.14
```

### Comparison

| Method         | Handles Decimals | Stops at Non-Digits | Recommended           |
| -------------- | ---------------- | ------------------- | --------------------- |
| `Number()`     | ✅ Yes           | ❌ No (returns NaN) | ✅ Most cases         |
| `parseInt()`   | ❌ No            | ✅ Yes              | ✅ Integer extraction |
| `parseFloat()` | ✅ Yes           | ✅ Yes              | ✅ Decimal extraction |
| `+value`       | ✅ Yes           | ❌ No               | ⚠️ Quick but unclear  |

---

### 2️⃣ Number → String

```js
String(123)(
	// "123"
	123
).toString(); // "123"
123 + ""; // "123" (implicit coercion)
```

> [!TIP] > **Best Practice**
> Use `String()` or `.toString()` for clarity.

---

### 3️⃣ Any → Boolean

```js
Boolean(0); // false
Boolean(1); // true
Boolean("hi"); // true
Boolean(""); // false
Boolean(null); // false

// Shorthand: Double NOT
!!value; // Converts to boolean
!!"hello"; // true
!!0; // false
```

---

### 4️⃣ Object → Primitive

JavaScript calls `valueOf()` then `toString()` on objects. You can override these methods!

```js
const money = {
	amount: 1000,
	valueOf() {
		return this.amount;
	},
};

money + 500; // 1500 (uses valueOf)
String(money); // "1000"
```

## ✅ Best Practices

### 1. Always Use `===` Instead of `==`

```js
// ❌ BAD
if (value == null) {
}

// ✅ GOOD
if (value === null || value === undefined) {
}
```

### 2. Explicit Conversion at Boundaries

Convert types explicitly when receiving data from:

-   User input (forms)
-   APIs
-   Files

```js
// User input
const userInput = document.getElementById("age").value;
const age = Number(userInput); // Explicit conversion

if (isNaN(age)) {
	console.error("Invalid age");
}
```

### 3. Use `Number()` for Decimals, `parseInt()` for Integers

```js
const price = Number("19.99"); // 19.99
const quantity = parseInt("5", 10); // 5
```

### 4. Avoid Mixing BigInt and Number

```js
// ❌ BAD
1n + 1; // TypeError

// ✅ GOOD
1n + BigInt(1); // 2n
```

## 🔥 Real-World Examples

### Example 1: Form Validation

```js
function validateAge(input) {
	const age = Number(input);

	if (isNaN(age)) {
		return "Please enter a valid number";
	}

	if (age < 0 || age > 150) {
		return "Invalid age range";
	}

	return "Valid";
}
```

### Example 2: Safe Comparison

```js
// ❌ BAD - implicit coercion
if (userInput == 0) {
	// Matches 0, "0", false, "", []
}

// ✅ GOOD - explicit check
if (Number(userInput) === 0) {
	// Only matches the number 0
}
```

### Example 3: API Data Conversion

```js
// API returns strings
const apiResponse = {
	price: "19.99",
	quantity: "5",
};

// Explicit conversion
const total = Number(apiResponse.price) * Number(apiResponse.quantity);
console.log(total); // 99.95
```

## 🎓 Summary

| Type                    | Behavior                       | Recommendation                |
| ----------------------- | ------------------------------ | ----------------------------- |
| **Implicit (Coercion)** | JavaScript auto-converts types | ⚠️ Be aware, can cause bugs   |
| **Explicit (Casting)**  | Developer manually converts    | ✅ Preferred, code is clearer |

### Key Takeaways

> [!IMPORTANT] > **Golden Rules**
>
> 1. Always use `===` instead of `==`
> 2. Convert types explicitly when working with external data
> 3. Know the 7 falsy values
> 4. Don't mix `BigInt` and `Number`
> 5. Use `Number()`, `parseInt()`, `parseFloat()` intentionally
