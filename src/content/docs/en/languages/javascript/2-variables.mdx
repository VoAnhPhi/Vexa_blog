# Variables in JavaScript

## 📌 Variable Declaration Keywords

JavaScript provides three keywords for declaring variables: `var`, `let`, and `const`. Each has different characteristics and use cases.

---

## 🔸 The `var` Keyword

The `var` statement declares a variable with **function scope** or **global scope**. Variables can be initialized with a value or left undefined.

### Key Characteristics

> [!WARNING] > **Legacy Keyword** > `var` is considered outdated. Modern JavaScript prefers `let` and `const` for better scoping and fewer bugs.

#### 1. Hoisting Behavior

Variables declared with `var` are hoisted to the top of their scope, but their value is not assigned until the code execution reaches the assignment.

```js
console.log(a); // undefined (no error!)
var a = 10;
console.log(a); // 10
```

#### 2. Function Scope (Not Block Scope)

`var` is only limited to function scope, **not** block scope (`{}`).

```js
if (true) {
	var x = 5;
}
console.log(x); // 5 (accessible outside the block!)
```

#### 3. Can Be Re-declared

```js
var name = "Alice";
var name = "Bob"; // No error
console.log(name); // "Bob"
```

---

## 🔹 The `let` Keyword

The `let` statement declares a variable with **block scope**. Variables can be initialized or left undefined.

### Key Characteristics

> [!TIP] > **Modern Choice**
> Use `let` when you need a variable whose value will change. It's safer than `var` because it respects block scope.

#### 1. Block Scope

`let` variables only exist within the block `{}` where they're declared.

```js
if (true) {
	let y = 10;
	console.log(y); // 10
}
console.log(y); // ReferenceError: y is not defined
```

#### 2. Temporal Dead Zone (TDZ)

While `let` variables are hoisted, they cannot be accessed before declaration.

```js
console.log(z); // ReferenceError
let z = 20;
```

> [!NOTE] > **Temporal Dead Zone (TDZ)**
> The period between entering a scope and the variable declaration is called the TDZ. Accessing the variable during this time throws an error.

#### 3. Cannot Be Re-declared

```js
let name = "Alice";
let name = "Bob"; // SyntaxError: Identifier 'name' has already been declared
```

---

## 🔷 The `const` Keyword

The `const` statement declares a variable with **block scope** that **cannot be reassigned** after initialization.

### Key Characteristics

> [!IMPORTANT] > **Must Be Initialized** > `const` variables must be assigned a value when declared. You cannot declare a `const` without an initial value.

#### 1. Must Be Initialized

```js
const pi; // SyntaxError: Missing initializer in const declaration
const pi = 3.14; // Correct
```

#### 2. Cannot Be Reassigned

```js
const pi = 3.14;
pi = 3.14159; // TypeError: Assignment to constant variable
```

#### 3. Objects and Arrays Are Mutable

> [!WARNING] > **Reference vs Value**
> With `const`, you cannot reassign the **variable itself**, but you **can modify the contents** of objects and arrays.

```js
const arr = [1, 2, 3];
arr.push(4); // ✅ OK - modifying contents
arr[0] = 10; // ✅ OK - modifying contents
arr = [10, 20]; // ❌ TypeError: Assignment to constant variable

const person = { name: "Alice" };
person.name = "Bob"; // ✅ OK - modifying property
person = {}; // ❌ TypeError: Assignment to constant variable
```

---

## 📊 Comparison Table

| Keyword   | Scope           | Hoisting        | Re-declaration | Reassignment   | Notes                                 |
| --------- | --------------- | --------------- | -------------- | -------------- | ------------------------------------- |
| **var**   | Function/Global | Yes (undefined) | ✅ Allowed     | ✅ Allowed     | Not limited to block `{}`             |
| **let**   | Block `{}`      | Yes (TDZ)       | ❌ Not allowed | ✅ Allowed     | Safer than `var`                      |
| **const** | Block `{}`      | Yes (TDZ)       | ❌ Not allowed | ❌ Not allowed | Use for constants or fixed references |

> [!TIP] > **Best Practice**
>
> -   Use `const` by default
> -   Use `let` if you need to reassign the variable
> -   Avoid `var` in modern JavaScript

## 🏗️ Hoisting

### What is Hoisting?

**Hoisting** is a JavaScript mechanism where variable and function **declarations** are moved to the top of their scope during the compilation phase, before code execution.

> [!NOTE] > **Only Declarations Are Hoisted**
> Only the declaration is hoisted, **not the initialization**. The value assignment stays in place.

### Hoisting with `var`

```js
console.log(myVar); // undefined
var myVar = 5;
console.log(myVar); // 5

// Interpreted as:
// var myVar;           // Declaration hoisted
// console.log(myVar);  // undefined
// myVar = 5;           // Assignment stays here
// console.log(myVar);  // 5
```

### Hoisting with `let` and `const` (TDZ)

```js
console.log(myLet); // ReferenceError
let myLet = 10;

console.log(myConst); // ReferenceError
const myConst = 20;
```

### Hoisting with Functions

**Function declarations** are fully hoisted (including the function body).

```js
sayHello(); // "Hello!" - works!

function sayHello() {
	console.log("Hello!");
}
```

> [!TIP] > **Function Expressions Are Not Fully Hoisted**
> If you assign a function to a variable, only the variable declaration is hoisted, not the function itself.

```js
greet(); // TypeError: greet is not a function

var greet = function () {
	console.log("Hi!");
};
```

### Summary

| Type                     | Hoisting Behavior                                                  |
| ------------------------ | ------------------------------------------------------------------ |
| **var**                  | Declaration hoisted, value is `undefined`                          |
| **let, const**           | Declaration hoisted, but in TDZ (cannot access before declaration) |
| **function declaration** | Fully hoisted (including body)                                     |
| **function expression**  | Only variable declaration hoisted                                  |

## 📝 Variable Naming Rules

Choosing good variable names makes your code more readable and maintainable.

### JavaScript Naming Conventions

> [!TIP] > **Follow Conventions**
> Consistent naming conventions make your code easier to read and understand, especially when working in teams.

#### 1. **camelCase** (Recommended for JavaScript)

First word lowercase, subsequent words capitalized.

```js
let firstName = "John";
let userAge = 25;
let isLoggedIn = true;

// Built-in examples
getElementById;
querySelector;
addEventListener;
```

#### 2. **PascalCase** (For Classes/Constructors)

All words capitalized, including the first.

```js
class UserProfile {}
class ShoppingCart {}

function Person(name) {
	this.name = name;
}
```

#### 3. **snake_case** (Not common in JavaScript)

All lowercase with underscores.

```js
let first_name = "John"; // Not typical in JS
let user_age = 25;
```

#### 4. **SCREAMING_SNAKE_CASE** (For Constants)

All uppercase with underscores, typically for true constants.

```js
const MAX_VALUE = 100;
const API_KEY = "abc123";
const DEFAULT_TIMEOUT = 5000;
```

## 🌍 Scopes (Variable Visibility)

**Scope** determines where variables are accessible in your code.

### Three Main Scopes

| Scope Type   | Description                               | Keywords              |
| ------------ | ----------------------------------------- | --------------------- |
| **Global**   | Accessible everywhere in the file/program | `var`, `let`, `const` |
| **Function** | Accessible only inside the function       | `var`, `let`, `const` |
| **Block**    | Accessible only inside `{}`               | `let`, `const` only   |

### Examples

#### Global Scope

```js
let globalVar = "I'm global";

function test() {
	console.log(globalVar); // Accessible
}

test(); // "I'm global"
console.log(globalVar); // "I'm global"
```

#### Function Scope

```js
function myFunction() {
	var functionVar = "I'm in a function";
	console.log(functionVar); // Accessible
}

myFunction();
console.log(functionVar); // ReferenceError
```

#### Block Scope

```js
if (true) {
	let blockVar = "I'm in a block";
	const blockConst = "I'm also in a block";
	console.log(blockVar); // Accessible
}

console.log(blockVar); // ReferenceError
console.log(blockConst); // ReferenceError
```

> [!IMPORTANT] > **var Does Not Respect Block Scope**
> This is one of the main reasons to avoid `var` in modern JavaScript.

```js
if (true) {
	var leakyVar = "I leak out!";
}
console.log(leakyVar); // "I leak out!" (not recommended!)
```
