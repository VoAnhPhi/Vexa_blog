## Comparison Operators

Compare two values and return `true` or `false`.

| Operator | Meaning | Example | Result |
| -------- | ------- | ------- | ------ |
| `==` | Equal (loose) | `5 == "5"` | `true` |
| `===` | Equal (strict) | `5 === "5"` | `false` |
| `!=` | Not equal (loose) | `5 != "5"` | `false` |
| `!==` | Not equal (strict) | `5 !== "5"` | `true` |
| `>` | Greater than | `7 > 3` | `true` |
| `<` | Less than | `3 < 5` | `true` |
| `>=` | Greater than or equal | `5 >= 5` | `true` |
| `<=` | Less than or equal | `4 <= 2` | `false` |

---

### == vs === (Loose vs Strict)

<Tabs>
  <TabItem label="== (Loose)">
    **Coerces types** before comparing — can cause surprises:

    ```js
    5 == "5";      // true  (string → number)
    0 == false;    // true  (false → 0)
    "" == false;   // true  ("" → 0, false → 0)
    null == undefined; // true (special rule)
    null == 0;     // false (null only == undefined)
    ```
  </TabItem>
  <TabItem label="=== (Strict)">
    **No type coercion** — must be same type AND same value:

    ```js
    5 === "5";     // false (different types)
    0 === false;   // false
    "" === false;  // false
    null === undefined; // false
    NaN === NaN;   // false ← special case!
    ```
  </TabItem>
</Tabs>

<Aside type="tip" title="Best Practice">
**Always use `===` and `!==`** — avoid unexpected results from type coercion. See [Equality Comparisons](/en/languages/javascript/7-equality-comparisons/) for details.
</Aside>

### String Comparison

Strings are compared by **Unicode** order (character by character):

```js
"a" < "b";      // true (97 < 98)
"abc" < "abd";  // true
"a" < "B";      // false (97 > 66) — uppercase has smaller code!
"10" < "9";     // true — compares as strings, not numbers!
```

<Aside type="caution" title="Watch out!">
When comparing **strings containing numbers**, JavaScript compares by Unicode, NOT by numeric value. Cast first: `Number("10") < Number("9")` → `false`.
</Aside>

## Logical Operators

Work with boolean values or "truthy/falsy".

| Operator | Meaning | Example | Result |
| -------- | ------- | ------- | ------ |
| `&&` | AND | `true && false` | `false` |
| `\|\|` | OR | `true \|\| false` | `true` |
| `!` | NOT | `!true` | `false` |

---

### Short-circuit Evaluation

<Tabs>
  <TabItem label="&& (AND)">
    Returns the **first falsy value**, or the last value if all are truthy:

    ```js
    true && "hello";   // "hello"
    false && "hello";  // false (stops immediately)
    0 && "hello";      // 0

    // Use case: run code when condition is true
    user && user.save();
    ```
  </TabItem>
  <TabItem label="|| (OR)">
    Returns the **first truthy value**, or the last value if all are falsy:

    ```js
    "" || "Guest";      // "Guest"
    0 || 42;            // 42
    "hello" || "world"; // "hello"

    // Use case: default values
    let name = input || "Guest";
    ```
  </TabItem>
  <TabItem label="?? (Nullish)">
    Returns right side only when left side is `null`/`undefined` — does **not** include `0`, `""`, `false`:

    ```js
    0 || 10;    // 10 ← wrong if 0 is a valid value
    0 ?? 10;    // 0  ← correct!

    null ?? "default";      // "default"
    undefined ?? "default"; // "default"
    false ?? "default";     // false (not null/undefined)
    ```
  </TabItem>
</Tabs>

  </TabItem>
</Tabs>

## Conditional Operator (Ternary)

The conditional (ternary) operator allows writing concise `if–else` statements **as an expression**.

### Syntax

```js
condition ? valueIfTrue : valueIfFalse;
```

### Examples

<Tabs>
  <TabItem label="Basic">
    ```js
    let age = 20;
    let access = (age >= 18) ? "Allowed" : "Denied";
    console.log(access); // "Allowed"
    ```
  </TabItem>
  <TabItem label="In JSX/templates">
    ```jsx
    // React JSX — ternary for conditional rendering
    return (
      <div>
        {isLoggedIn ? <Dashboard /> : <Login />}
      </div>
    );
    ```
  </TabItem>
  <TabItem label="Nested (avoid!)">
    ```js
    // ❌ Hard to read
    const grade = score >= 90 ? "A"
               : score >= 80 ? "B"
               : score >= 70 ? "C"
               : "F";

    // ✅ Use if...else or object lookup instead
    ```
  </TabItem>
</Tabs>

<Aside type="tip" title="When to use ternary?">
- **Use**: simple conditional value assignment
- **Don't use**: complex logic, multiple branches, or side effects
</Aside>

## Summary

| Group | Key Operators | Remember |
| ----- | ------------- | -------- |
| **Comparison** | `==` `===` `!=` `!==` `>` `<` `>=` `<=` | Always use `===` / `!==` |
| **Logical** | `&&` `\|\|` `!` `??` | Short-circuit + nullish coalescing |
| **Conditional** | `? :` | Only for simple expressions |
